# 今天 GitHub 趋势榜在说什么：skill 正在变成智能体的标配

今天刷了一圈 GitHub 趋势榜，16 个上榜项目里一半以上和 agent skill 有关。一个感觉很明显：大家不再只比谁的模型更强，而在比谁给智能体准备的“手艺”更好。

## 三种形态

**第一种，一页纸的原则。** 比如源自 Karpathy 那条推文的 andrej-karpathy-skills，一份 CLAUDE.md，四条行为规则：先想再写、简单优先、只改该改的地方、盯着目标。成本最低，见效也最直接。

**第二种，个人经验打包。** 比如 mattpocock/skills，把自己 .agents 文件夹里的 skill 公开：TDD、拆需求、复盘，各管一摊，都是平时真正在用的东西。

**第三种，整套框架。** 比如今天榜二的 obra/superpowers（32 万星），方法论加 skill 库加流程，整套搬走。还有 affaan-m/everything-claude-code，几十个 agent 定义、上百个 SKILL.md 文件，走的是大而全的路子。

## 两个新动向

**一是 skill 开始按行当分工。** 今天榜一的 Claude-BugHunter（17,167 星，一天涨了 1,716 星），82 个 skill 专做漏洞挖掘和外部红队，整理了 681 个已披露报告模式。以后大概每个行当都会有自己的 skill 包。

**二是判断力也被写成了规则。** 设计有 impeccable、hallmark、taste-skill，安全审计有 cloudflare/security-audit-skill（一周涨了一万多星）。审美、安全这些过去靠“手感”的东西，现在也被写成智能体能照着执行的检查项。

## 我的一点心得

skill 的本质，是把人的经验压缩成智能体能直接用的操作手册。模型决定下限，skill 决定上限。接下来拼的不是谁模型大，而是谁的 skill 库更懂行。

学 skill 别贪多。先从一个顺手的开始：比如先抄 Karpathy 那四条规则，用顺了再按需往上加。今天榜上这些仓库，挑一个跟你手头活最贴的，先用起来，比收藏十个有用。
